# 智能递归解压工具（JieYa）

**exe 版 `智能递归解压工具.exe`（不需要装 Python）**：独立窗口软件（WebView2 内嵌原界面），双击直接打开界面，没有黑色命令行窗口，关掉窗口即退出。把文件或文件夹**拖到 `智能递归解压工具.exe` 图标上**，打开后会自动加入目标并开始解压。扩展名不对或没有扩展名的文件，也会按文件头（zip/rar/7z/gz/bz2/xz/zst/cab）识别；这类“靠文件头认出”的包解压后**保留原件**，不受「解压后删除原包」影响；docx/xlsx/jar/apk 等本身是 zip 的正常文件不会被拆。配置和账本读写 exe 旁边的 `config.json` / `已解压记录.json`。仍需本机装 7-Zip 或 WinRAR。重新打包：`py -3 -m pip install pyinstaller pywebview`，然后 `py -3 -m PyInstaller --onefile --windowed --name 智能递归解压工具 --distpath . --add-data "web;web" --add-data "open_folder.ps1;." JieYa.py`。

已修复子文件夹漏扫：现在会进入目标目录及解压结果中的各级普通子文件夹，继续处理其中的压缩包，包括“压缩包 → 文件夹 → 文件夹 → 内层压缩包”。普通文件夹不占用最大解压深度，重叠选择的目录只扫描一次；不跟随子目录符号链接或目录联接，避免循环。以前遗漏的包可直接选择其所在目录重新运行，无需清空已解压记录。程序已打开时，请关闭后台后重新运行 `启动.bat` 加载修复。

“打开目标文件夹”已补充资源管理器前台激活：按目标路径匹配窗口后恢复/激活，不永久置顶。`open_folder.ps1` 必须与 `JieYa.py` 同目录，使用 Windows 自带 PowerShell，无需额外依赖。目标是文件时打开其父目录。激活失败会显示提示。更新后如程序原先开着，关闭程序后重新双击 `启动.bat`，以载入新代码。

“浏览文件夹”和“选择压缩包”另走原生选择对话框：现已设置当前前台主界面为所属窗口，在初始化回调中激活对话框，不永久置顶。两个真实 Win32 选择窗口已做受控测试：所属窗口正确、位于前台、取消后返回空值；尚需在实际浏览器主界面点击确认。更新时请先取消旧弹窗，关闭工具及其黑色命令行窗口，再运行 `启动.bat`，仅刷新网页不能重载 Python 后端。

一个自动"解到底"的解压软件：压缩包里还有压缩包就继续解，`.mp4` / `.jpg` 伪装包也能识别，
文件名重复时自动改名，**绝不覆盖任何已有文件**。

## 快速开始

双击 **`启动.bat`** 即可。程序会自动打开一个独立窗口（Edge/Chrome 应用模式），
在里面选好文件夹，点「开始解压」。

关闭那个黑色命令行窗口 = 退出程序。

## 它到底做什么

### 1. 递归解压，直到没有压缩包
```
压缩包 A.zip
  └── B.7z
        └── C.zip
              └── deep.txt        ← 一路解到底
```
每解一层，会在压缩包旁边生成**同名文件夹**装内容（`A.zip → A\`），
然后自动进去找下一层压缩包，直到整个目录里再也找不到压缩包为止。

支持格式由本机的 7-Zip 决定，实际覆盖：
`zip / 7z / rar / tar / gz / tgz / bz2 / xz / lzma / zst / cab / iso / arj / lzh / wim / 分卷包 …`
加密压缩包会自动尝试密码字典。分卷压缩包只处理第一卷，不会重复解压。

### 2. 伪装包识别（.mp4 / .jpg）
指定后缀的文件会被**改名为 `.zip` 后强制尝试解压**——用来识别那些把压缩包改名成视频/图片的"伪装包"。

- 解压成功 → 生成内容文件夹，并把文件**改回原来的 `.mp4` / `.jpg` 名字**（可关闭）
- 解压失败 → 立刻**改名还原**，文件一个字节都不会变

因为默认是"一律强制改名尝试"，如果目录里有大量**真视频**，每次都会白试一遍。
这时可以打开选项里的 **「快速预检」**：先看文件头是不是 ZIP 特征，明显不是就跳过，速度能快几十倍。

### 3. 重名自动重命名
输出文件夹或文件重名时，自动追加序号，**永不覆盖**：
```
Same.7z   → Same\
Same.zip  → Same (1)\
```
做过的重命名次数会显示在统计卡片「重名自动重命名」里。

### 4. 重复运行不会重复解压
成功解压过的文件会按 `路径 + 大小 + 修改时间` 记账，重复点「开始」不会把整个目录再解一遍。
记录存在程序目录的 `已解压记录.json`，**不会在你的文件夹里留下任何标记文件**。
想强制重解，把选项里的「跳过已解压过的文件」关掉即可。

## 界面说明

| 区域 | 作用 |
|---|---|
| **1 选择目标** | 可加多个文件夹 / 压缩包。路径可以直接粘贴，「浏览文件夹」调用的是 Windows 原生选择框 |
| **2 选项** | 伪装扩展名、最大递归深度、密码字典、还原文件名、快速预检、解压后删除原包、跳过已解压 |
| **3 执行** | 开始 / 停止 / 打开目标文件夹，进度条与实时统计 |
| **4 实时日志** | 每一步都有记录，绿色=成功、橙色=警告、红色=失败 |

**密码字典**：界面上每行一个密码，按顺序自动尝试。第一行留空表示先试「无密码」。
默认已内置 28 个常见密码，成功的密码会直接在日志里显示出来。

## 其它用法

**命令行模式**（适合批量、脚本、计划任务）：
```bat
python JieYa.py --cli "D:\某个目录" "D:\另一个压缩包.rar"
python JieYa.py --cli "D:\某个目录" --force   # --force 忽略已解压记录，强制重解
```

**自检**（构造样例数据跑一遍全部规则，验证程序行为）：
```bat
python 自检.py
```
会检查三层嵌套、伪装包、加密包、重名改名、真视频不被破坏、重复运行不重复解压等 16 项。

子文件夹递归专项测试：`python -m unittest test_recursive -v`。使用临时样例和独立账本，覆盖已有目录、解压后多级目录、重叠目标、重复跳过、删除原包和解压深度限制，并检查 7-Zip 与内置 zipfile 两条路径。

## 常见问题

### 双击 `启动.bat` 弹出「Python was not found … 微软商店」

这是 Windows 的**「应用执行别名」陷阱**，不是你装错了。

系统里有个 `C:\Users\<你>\AppData\Local\Microsoft\WindowsApps\python.exe`，
它只有 **121 字节**，是个指向微软商店的假占位，却在 PATH 里排在最前面。
所以只要直接调用 `python`，就会选中这个假货。

`启动.bat` 已经处理了这种情况：它**不看文件名，而是把每个候选都实际执行一次来验证**，
假占位跑不出结果会被自动淘汰，然后继续往下找真正可用的解释器。

如果它还是报「没有找到可用的 Python 3.8+」，说明这台机器上确实没有可用的 Python，
此时它会打印 `python-help.txt` 里的中文说明，按里面两个方法任选一个即可：

1. 到 https://www.python.org/downloads/ 装 Python 3，安装时勾选 **Add python.exe to PATH**
2. 或到「设置 - 应用 - 高级应用设置 - 应用执行别名」里关掉 `python.exe` / `python3.exe`

### 界面里点按钮没反应／显示「未连接到解压服务」

说明浏览器里的页面和后台程序断开了。关掉那个黑色命令行窗口，重新双击 `启动.bat`。

### 端口 8765 被占用

不用管，程序会自动顺延到 8766、8767……

## 注意事项

- **解压是原地进行的**：输出文件夹就建在压缩包旁边。想保持原目录干净，请先把要处理的文件夹复制一份。
- 遇到需要密码但密码不对的压缩包，会记为「加密包未解开」并跳过，**不会中断整体流程**。
- 部分解压失败（文件损坏、下载不完整）会在日志中标红，其余文件继续处理。
- 程序只监听本机 `127.0.0.1`，外网无法访问。
- 解压内核需要本机装有 **7-Zip** 或 **WinRAR**。都没有时会退化为 Python 内置 `zipfile`（只支持 zip）。
